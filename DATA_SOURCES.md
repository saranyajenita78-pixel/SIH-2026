# DATA_SOURCES.md

This document records the provenance of every dataset used in PolarOps AI, per the
project's Data Integrity Policy. Categories used throughout:

- **REAL_OBSERVED** — actual observations from a legitimate public/authorized source
- **REAL_REFERENCE** — real factual/reference information, not sensor telemetry
- **SIMULATED_DEMO** — artificially generated data, used because real telemetry is unavailable
- **REAL_FORECAST** — official forecast product, kept separate from observations
- **MODEL_PREDICTION** — output generated by this project's own AI/ML models

---

## Dataset: Station reference metadata

- **Source:** Public knowledge (station names, approximate coordinates, region, founding year)
- **Station:** Maitri, Bharati
- **Type:** REAL_REFERENCE
- **Variables:** name, latitude, longitude, region, established year
- **Access:** Public
- **Processing:** None — used as-is in `config.py`
- **Limitations:** Coordinates are approximate/public-knowledge values, not surveyed GPS fixes.

## Dataset: Maitri / Bharati Automatic Weather Station (AWS) data

- **Source organization:** NCPOR (National Centre for Polar and Ocean Research) /
  National Polar Data Centre (NPDC)
- **Station:** Maitri, Bharati
- **Type intended:** REAL_OBSERVED
- **Variables (when available):** temperature, humidity, pressure, wind speed, wind direction
- **Download method:** Manual CSV export from the NCPOR/NPDC portal, placed by the user into
  `data/raw/ncpor/<station>_aws.csv`
- **Access status:** The application supports a public live-page fetch through
  `src/data/ncpor_live.py` and an official local CSV export through `src/data/ncpor_loader.py`.
  Live fetching could not be executed inside this build environment because outbound internet
  access is disabled.
- **Processing performed (once a real file is supplied):** column-name normalization,
  timestamp parsing, missing-value interpolation, numeric-range validation, duplicate removal.
- **Current status in this build:** no real station file is bundled; REAL mode reports an
  ingestion error if the live public page is unreachable. DEMO mode uses the simulator.
- **Limitations:** NCPOR/NPDC dataset availability, access conditions, and licensing vary by
  dataset and were not independently re-verified for this submission — consult the NCPOR/NPDC
  portal directly for current access terms before using this pathway with real data.

## Dataset: Equipment telemetry (generators, heating, communications)

- **Source:** Project simulator (`src/data/simulator.py`)
- **Station:** Maitri, Bharati (8 equipment units total)
- **Type:** SIMULATED_DEMO
- **Variables:** temperature, vibration, load %, voltage, operating hours
- **Access:** N/A — not a real feed. No public real-time Antarctic station equipment
  telemetry feed is known to exist for this project to connect to.
- **Processing:** Deterministic, relationship-driven generation — equipment load and
  temperature respond to the same weather series used elsewhere, so cause→effect chains
  (e.g. extreme cold → higher heating demand → higher generator load → higher equipment
  stress) are visible and reproducible, not random noise.
- **Limitations:** Not derived from any real equipment. Absolute values (e.g. "72% health")
  should be read as illustrative of the *method*, not as real equipment condition.

## Dataset: Energy production/consumption

- **Source:** Project simulator (`src/data/simulator.py`)
- **Type:** SIMULATED_DEMO
- **Variables:** production (kW), consumption (kW), fuel level (%), generator load (%)
- **Processing:** Consumption is driven by the weather series (cold penalty) and by the
  active Demo Mode scenario; fuel level depletes deterministically from consumption.

## Dataset: Inventory

- **Source:** Project configuration (`config.py`) + simulator scenario multiplier
- **Type:** SIMULATED_DEMO
- **Variables:** item, category, quantity, minimum stock, daily usage, lead time, criticality
- **Limitations:** Illustrative starting stock levels and consumption rates, not real
  station inventory records.

## Dataset: Logistics

- **Source:** Project simulator (`src/data/simulator.py`)
- **Type:** SIMULATED_DEMO
- **Variables:** item, transport mode, expected arrival, cargo priority, weather dependency,
  route status
- **Limitations:** These are illustrative example shipments, not real current resupply
  schedules for Maitri or Bharati.

## Dataset: Model predictions (anomaly scores, forecasts, risk scores)

- **Source:** This project's own models (`src/ml/`, `src/risk/`)
- **Type:** MODEL_PREDICTION
- **Limitations:** See MODEL_CARD.md. No real labeled ground truth exists for equipment
  failures or historical Antarctic operational incidents for this project to validate against;
  evaluation is limited to internal diagnostics (baseline vs. scenario score separation,
  standard regression metrics on the energy forecast).

## 2026 real-source integration

- **NCPOR / NPDC live weather:** REAL_OBSERVED. In REAL mode the adapter reads a local official CSV export when present; otherwise it can fetch the latest published observation from the public NPDC station page for Maitri/Bharati.
- **NCPOR historical weather / snowfall:** REAL_OBSERVED when an official export is supplied under `data/raw/ncpor/historical/`.
- **IMD Polar WRF:** REAL_FORECAST. Official forecast exports are accepted under `data/raw/imd/<station>_polar_wrf.csv` or `.json`. Forecast values are intentionally not relabelled as observations.
- **Equipment / energy / inventory / logistics / communication:** SIMULATED_DEMO in this prototype unless an authorised station telemetry feed is supplied.
- **AI model outputs:** MODEL_PREDICTION.

The dashboard runs **REAL** data mode by default; DEMO mode remains available for tests/development. REAL mode never silently substitutes simulated weather when NCPOR data cannot be obtained; it reports the ingestion error instead.


## SIH demo data contract

- **NCPOR / NPDC**: live Maitri/Bharati environmental observations are tagged `REAL_OBSERVED`. A successful live observation is cached locally under `data/processed/ncpor_cache/` for offline continuity.
- **IMD Polar WRF**: the adapter accepts official IMD export files under `data/raw/imd/` and tags them `REAL_FORECAST`. The application never labels synthetic forecast values as IMD.
- **Equipment / energy / inventory / logistics**: `SIMULATED_DEMO` because internal station telemetry is not publicly available to this prototype. These streams are still causally coupled to weather/scenario inputs so the Digital Twin can demonstrate failure propagation.
- **AI outputs**: `MODEL_PREDICTION` / decision-support output. Human approval is required before consequential action.

### IMD file format

Put official exports at:

- `data/raw/imd/maitri_polar_wrf.csv`
- `data/raw/imd/bharati_polar_wrf.csv`

Minimum field: `timestamp` (aliases such as `valid_time` are accepted). Optional fields include temperature, relative humidity, pressure, wind speed and wind direction. Wind speed in knots is converted to km/h when the source field is named `wind_speed_knots`.

## Verified public source registry (checked September 2026)

- **NCPOR/NPDC Maitri latest published observation:** https://data.ncpor.res.in/live/maitri
- **NCPOR/NPDC Bharati latest published observation:** https://data.ncpor.res.in/bharati/live
- **NCPOR Antarctic meteorological data / source registry:** https://data.ncpor.res.in/graph
- **NCPOR data availability / historical datasets:** https://data.ncpor.res.in/newhtml/
- **NCPOR Maitri AWS historical dataset index:** https://data.ncpor.res.in/search/data/25/
- **IMD Polar WRF official documentation / forecast service:** https://mausam.imd.gov.in/imd_latest/contents/ar2021.pdf
- **IMD NWP SOP (Polar WRF over Bharati/Maitri):** https://mausam.imd.gov.in/imd_latest/contents/pdf/nwp_sop.pdf

Important: a public NCPOR page is a published observation source; the application records its observation timestamp and should not label an old observation as a real-time sensor stream. IMD Polar WRF is a forecast/model product, not an observation. The prototype only labels IMD values `REAL_FORECAST` when an official export/feed is actually supplied.

### Historical snowfall / snow data

NCPOR publicly lists historical Maitri atmospheric datasets, including an AWS dataset index
with IMD 1985-2016 and SASE 2006-2015 collections. The current NCPOR graph interface exposes
temperature, pressure, wind and humidity parameters directly, not a stable public snowfall API.
IMD's Polar WRF documentation also shows snowfall forecast products for Maitri and Bharati.
Therefore the application only computes an exact historical maximum snowfall date when an
authorised historical export containing a snowfall field is loaded; it never invents the value.
